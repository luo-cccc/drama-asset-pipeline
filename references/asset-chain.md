# 两段链：MJ 画风基准 → GPT Image 2 资产图

本文给出 A 层资产的实际出图写法。链条分两段，职责不同，不能互换。

## 为什么分两段

| 段 | 负责 | 不负责 |
| --- | --- | --- |
| Midjourney | 美术方向、媒介、质感、光照逻辑、配色倾向 | 版式、分区、多视图、精确结构、文字 |
| GPT Image 2 | 结构化资产图、多视图版式、首帧合成、定点编辑 | 美术方向（继承自 MJ 段） |

分工依据是能力差异：MJ 在"白底分区、左右两栏、2×2 网格"这类版式要求上不可控；GPT Image 2 听版式指令、能接多图输入、编辑端点能以首图为编辑对象而其余作参考。

另有一条关于素材来源的约束：**部分视频平台限制含真人面孔的参考图**，只接受模型既往输出或已授权素材。具体限制口径按目标平台当次核实，不预设。这类平台上合成路径是前提而非偏好；全部身份来自文字设计时该约束不适用。

### 第一段可以跳过的情形

MJ 段的产出是画风基准。当画风已由其他方式确定——用户给了质感参考图、已确认了文字风格方向、或本项目的其他资产已经建立了统一画风——不必为每个新资产再出一张 MJ 图，直接进第二段，用已确认的画风依据。

必须走第一段的情形：项目画风尚未确立，需要先看到实际画面才能确认美术方向。这是第一段的真正用途，不是流程上的必经环节。

**MJ 底图是中间件。** 它确立这个角色或场景"长什么风格"，不作为提交给视频模型的资产图。账本里记在 `mj_base`，与 `asset_images` 分开。常见错误是把 3:4 的 MJ 半身图直接当人物资产传上去——画幅和版式都不对。

## 第一段：MJ 画风基准

项目画风尚未确立时出，目的是锁定美术方向。不求版式，不求完整结构。画风确立后的后续资产沿用同一方向，不必每个都再出一张。

写法要点：

- 写清媒介与质感。这是本段的唯一目的，其余从简。
- 人物用半身或全身单人，构图简单，不做设定板尝试。
- 场景用主机位广角，无人。
- 道具用近景单件。
- 全剧共用一套质感描述，不要每个资产各写一套——那会导致资产之间画风不统一。

参数：统一 3DCG 默认下人物 `--ar 3:4`、场景与道具 `--ar 16:9`，均配 `--raw --s 150`。明确要求水彩、水墨等具名媒介时，只保留本工作流对应的画幅，不照搬 `--raw` 和 `--s`。

本段产出确认后，它的实际画面成为第二段的画风依据。第一段的提示词只表达意图，不代表画面真的实现了每一项。

## 第二段：GPT Image 2 资产图

以 MJ 图作**画风参考**，不是身份来源。身份、结构、配色从文字设定与世界观来。

### 参考图职责必须逐项声明

每张输入图写明它提供什么、禁止带入什么。一张图承担多个职责时分别声明。

| 输入 | 提供 | 禁止带入 |
| --- | --- | --- |
| MJ 画风基准 | 媒介、质感、光照倾向、配色关系 | 原构图、原姿态、原背景、画幅 |
| 目标角色身份图 | 脸、骨相、体型、服装结构 | 原背景、原棚拍光、画外物件 |
| 场景结构图 | 已看见的结构、地标、通路、尺度 | 原有人物、原天气时段 |
| 版式参考 | 分区与排布 | 其中的人物、场景、配色 |

### 人物资产图

产出两类：身份母图（确立脸），多视图设定板（确立服装与体型的各角度关系）。

两条有机制依据的写法：

**多视图必须单次生成。** 分次生成各视角必然漂移——两次生成得不到同一张脸。把全部视角放在一张图里一次出，视角之间才可能同源。

**底色用中性灰，不用纯白。** 纯白与主体形成最大对比，而视频模型在高对比边缘处最容易放大错误，把边缘呼吸和轮廓不稳定烘进运动里。中性灰降低主体与背景对比，被当作参考帧读取时边缘更干净。同时要求背景中性但**主体不被中性化**：肤色按设计的真实色呈现，不被背景染冷或冲淡。

设定板的版式按实际需要定。默认的一种：全身正面、严格 90 度侧面、背面三视，加正面头肩、45 度头肩、侧面头像、正脸近景四格。各视图共享同一身高比例、同一套服装结构、同一光源方位；只有观察方向变化，不每个视图重新布成正面平光。

### 场景资产图

产出主机位场景板（无人），以及按镜头需要增补的机位。

**增量机位按需才出**，并记录是为哪一镜出的。不预先补齐三视图或比较网格——用不到的机位是纯浪费。

**另外维护一份文字结构锚点**：地标、建筑与道路连接、光源方位、尺度关系、已确认但画面未显示的设计。短剧同一场景会跨十几个镜头换机位，新机位的一致性主要靠这份文字锚点，不靠参考图——原机位的图不能充当新机位的结构依据。

可动部件（门窗、抽屉）在场景板里画成稳定的默认状态，需要其他状态时从该板编辑。

### 道具资产图

净底单件近景，完整展示形制与材质。形制复杂时加关键结构局部。

持有关系不进道具资产。谁拿着它、用哪只手、怎么握，都在首帧合成阶段处理。

## 首帧合成

这是三平台交集路线上的关键产出，**在槽位路由之后做**——首帧要装什么取决于路由结论。Kling 与 Wan 上场景与道具并入首帧，首帧必须完整承载它们；Seedance 上它们单独直传，首帧只需与之不冲突。

输出是某一镜开始那一刻的画面。输入按层分三类，在同一条提示词里并存并各自声明来源：

| 层 | 在首帧里的来源 |
| --- | --- |
| A | 已锁定的资产图 |
| B | 完整文字身份描述（它没有资产图） |
| C | 简短文字描述，只写本镜可见的部分 |

C 层出现在画面里就照写。"不出图"指不做资产图，不是不出现在画面里；写法从简，给类别、大致形貌和位置即可，不追求跨镜一致。

- 写镜头开始的状态，不写镜头里的主要动作。
- 逐张声明输入图的职责。
- 人物在画面里的位置、朝向、姿态逐人写一句。
- 取景写清画面上下边缘落在身体哪里。
- 固定物件写出可见形态与开合状态——只在场景板里写过的事实不会自动继承到这里。

**已知失败项，无已验证解法**：多人同框的左右关系、持有道具的手、门窗开合方向。写明在提示词里也可能出错。交付前放大核对实际画面，不以"提示词已写明"作为通过依据。需要镜像或定点编辑修正时，记录来源、操作与它改变的设计事实——镜像会把合页、纹样、配饰的左右一并翻转，所以进深方向的错误（门朝里还是朝外开）镜像改不了，只能定点编辑。

## 尾帧

目标平台支持首尾帧、且本镜需要指定结束状态时才做。尾帧写该镜结束那一刻的状态，与首帧用同一套输入和画风依据。

做法是从该镜首帧做定点编辑，只改变镜内实际发生变化的部分（位置、姿态、持物、门窗开合、新增损伤），保留机位、光照、空间和未受影响的内容。这比另起一张合成更能保证首尾同源。

尾帧不进资产库，属于该镜的提交输入，并占目标平台的图片额度，计入槽位预算。

**不要把"上一段的实际末帧"与"本段尾帧"混为一谈**：前者是已生成的视频画面，用于段间接续；后者是本次提交的控制输入。接续见 [review.md](review.md) 的视频专项。

## 媒介一致性

**具名媒介替换 CG 描述，不叠加。** 要求水彩、水墨或绘画时，不往提示词里混入 PBR、次表面散射、全局光照这类 CG 术语。

**资产图的呈现光照与场景光照分开。** 设定板是呈现图，用中性略冷的均匀光；场景板按该场的时间天气组织光照。两者的材质表现和完成度要兼容。

**写实措辞会把非写实项目拉向写实。** 动画或风格化项目里不写"真实皮肤质感""毛孔""照片级"这类词。

## 边界

**不生成图片。** 本文给的是提示词写法。

**资产图的身份保持率没有证据。** 单次生成多视图、中性灰底这两条有机制说明，但缺 A/B 数据。GPT Image 2 在这条链上的实际表现需要实测，不预先承诺。

**定点编辑的能力范围未经完整验证。** 编辑端点以首图为编辑对象、遮罩只作用于首图是文档行为；具体编辑任务能否达成需逐项实测。

**提示词写明不等于画面达成。** 提示词、参考图、种子和风格代码都不保证几何或像素锁定。本技能不生成控制图、不重建三维、不配置生图工具。
