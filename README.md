# 短剧资产流水线

把剧本拆成人物、场景、道具资产，判定哪些值得出参考图，并让这些资产在多镜头里保持一致。只交付文字，不生成图片或视频。

两个决定贯穿全流程：**哪些资产值得出图**，以及**出好的图怎么进视频模型**。这两个决定由镜头清单和目标平台能力推出，不靠对戏份轻重的主观判断。

## 流程

```
剧本盘点 → 交叉表 → 分层 → 定画风 → 出资产图
        → 槽位路由 → 合成首尾帧 → 逐镜提交 → 返图检查
```

首尾帧合成排在槽位路由之后，因为首帧要装什么取决于路由结论：Kling 与 Wan 上场景道具并入首帧，Seedance 上它们单独直传。资产图跨镜复用，首尾帧逐镜生成，是两件事。

顺序固定：分层依赖出现次数，出现次数依赖镜头清单。跳过交叉表会同时产生两种浪费——生成从未被引用的资产，以及漏掉本该锁定的资产。

## 分层判据

不问"这个资产重要吗"（主观，按职业、戏份或年龄判断都会失准），问**不一致会不会被看出来**。它分解成两个可判定的量：

- **文字可复现性**：同一段文字跑两次算不算同一个东西。脸不行，普通木箱行。
- **出现次数**：从镜头清单统计，写成实际镜号。

按顺序判，第一个匹配的即为该层：

| 层 | 条件 | 产出 |
| --- | --- | --- |
| C | 文字可复现 | 不出图，写进镜头提示词 |
| A | 不可复现 **且** ≥2 镜 | 完整资产图组，进库锁定 |
| B | 不可复现 **且** 仅 1 镜 | 只在该镜首帧里体现，不进库 |

先判可复现性再判镜数，这个顺序消除了"1 镜、不可复现、不需精确"的归属歧义。只出现一镜的有名配角落 B（脸要在那一镜成立），一群无名路人落 C（没人分辨得出换没换）。

状态另走一条并行判据：**跨镜持续**的（淋湿、受伤、破损）是资产新版本；**单镜内**的（表情、姿态、持物手）是镜头内容，不建资产。混淆这两类会让一个角色占掉七八个编号，其中多数只用一次。

状态版本继承母资产的层，不单独分层。要不要为它出图再判一次：局部且文字写得住的（肩部血迹）不出图，走镜头文字；整体外观改变、文字写不住的（全身淋湿）从基准设定板**定点编辑**出一张状态板——不重新生成整板，因为重新生成会得到另一张脸。

变化发生的那一镜，首帧取变化之前的版本：淋湿发生在 S02-02 镜内，则 S02-02 首帧是干的，S02-03 起用湿版。恢复条件按剧情判定，不默认写成"不恢复"。

## 三平台的参考机制

核查日期 2026-11-06，来源为各平台官方文档。

| 平台 | 参考图上限 | 首帧是否占该上限 | 寻址 |
| --- | --- | --- | --- |
| Seedance 2.5 | 30 图 | 占 | 位置序号 |
| Seedance 2.0 | 9 图 | 占 | 位置序号 |
| Kling 4 | 10 图 UNVERIFIED | 占 UNVERIFIED | 未见文档化语法 |
| Wan 3.0 | UNKNOWN | 不适用，两模式互斥 | 未见文档化语法 |

首帧与尾帧各从参考额度里扣一张，所以 Seedance 2.0 的 9 张意味着首帧 + 尾帧 + 7 张参考。统一口径：

```
本镜占用 = 首帧 1 + 尾帧（需要时 1）+ 直传的 A 层资产数
```

三条推论：Wan 的首帧模式与参考图模式互斥，本流水线固定选首帧；Kling 上参考与关键帧抢同一预算；Seedance 位置寻址，**上传顺序带语义**。

三族交集是**首帧承载身份**。这是整套方案的轴：设定板的首要用途是作为合成逐镜首帧的原料，不是上传素材。同类方案普遍假定参考槽可随意使用，在 Wan 上整体失效。

路由表是硬路线，不是超限才启用的降级方案——Kling 与 Wan 上场景道具一律并入首帧，不因还有余额改为直传。Kling 上参考与关键帧抢预算时**关键帧优先**：首尾帧先占位，余额才给设定板。

真正超限时的保留顺序是 **首帧 > 尾帧 > 人物身份 > 场景 > 道具**，削减只发生在直传的 A 层资产之间（B、C 层本来就不占参考槽），同类按出现镜数升序先削。不按主角配角判断——分层体系只产出 A/B/C 和镜数。

交付形态也分平台：Seedance 用带编号的槽位映射表（顺序带语义），Kling 与 Wan 没有文档化的引用语法，交付不编号的上传清单。

## 两段链

| 段 | 负责 | 不负责 |
| --- | --- | --- |
| Midjourney | 美术方向、媒介、质感、光照逻辑 | 版式、分区、多视图、精确结构 |
| GPT Image 2 | 结构化资产图、多视图版式、首帧合成、定点编辑 | 美术方向（继承 MJ） |

分工依据能力差异：MJ 在白底分区版式上不可控；GPT Image 2 听版式指令、能多图输入、编辑端点以首图为编辑对象。

另有一条素材来源约束：**部分视频平台限制含真人面孔的参考图**，只接受模型既往输出或已授权素材；具体口径按目标平台当次核实。这类平台上合成路径是前提，不是风格偏好。

**MJ 底图是中间件，不是资产图。** 账本分开登记，否则会把 3:4 的 MJ 半身图当人物资产提交。

**第一段可以跳过**：画风已由其他方式确立时（有质感参考图、已确认文字风格、或本项目其他资产已建立统一画风），直接进第二段。MJ 段的用途是确立画风，不是流程上的必经环节。

两条有机制依据的写法：多视图**单次生成**（分次必然漂移）；底色用**中性灰而非纯白**（纯白的高对比边缘会让视频模型放大边缘呼吸和轮廓不稳定，中性灰边缘更干净，同时要求背景中性但主体不被中性化）。

## 已知限制

**待实测**：Kling 的 10 图含首尾帧来自第三方封装层 spec（官方 API 文档为纯客户端渲染，取不到正文），可能不等于原生上限。Wan 3.0 的参考图张数官方未公布，已确认的只有互斥关系。

**无已验证解法**：多人同框的身份相互污染；首帧里的左右关系、持有道具的手、门窗开合方向。这些写明在提示词里也可能出错，交付前须放大核对实际画面。

**无实图证据**：单次生成多视图、中性灰底这两条有机制说明但缺 A/B 数据。GPT Image 2 在这条链上的实际身份保持率需要实测，本技能不预先承诺。

**无自动一致性度量**：身份核对靠人眼，没有嵌入距离或相似度分数。不给出"一致性 9/10"这类无标准的量化结论。

分层决定哪些资产值得投入一致性手段，不保证一致性达成。实际一致性取决于平台参考机制和首帧质量，必须检查返回画面。
